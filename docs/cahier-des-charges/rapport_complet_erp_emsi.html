1. Ce qui manque aux ERPs génériques : La Réalité EMSI

Comprendre le terrain pour construire un système qui ne sera jamais rejeté par l'administration

Multi-Sites dans la même ville

À Casablanca ou Rabat, l'EMSI possède plusieurs sites (ex: Centre, Maârif, Orangers, Roudani / Agdal, Hassan). Les professeurs permanents et vacataires changent souvent de site dans la même journée. Le planificateur doit intégrer une durée de battement inter-sites obligatoire pour éviter des retards chroniques.

Les Enseignants Vacataires

Une part majeure des modules techniques de 4ᵉ/5ᵉ année est assurée par des experts industriels vacataires. Leurs créneaux sont ultra-contraints (soirs, samedis, jours spécifiques). Un ERP doit gérer leurs fiches de disponibilité, émargements numériques et validation d'heures réelles pour la paie.

L'Anonymat & Jurys de Délibération

La gestion des examens finaux exige un numéro d'anonymat avec scellés sur les copies, une répartition surveillant/étudiant équitable, et des délibérations semestrielles avec règles d'élimination (note < 7/20), compensation modulaire (moyenne ≥ 12/20) et session de rattrapage.

4. « GRILL-ME » : Le Crash Test du Jury PFE

Les questions techniques, architecturales et métier que le jury va obligatoirement vous poser le jour J

Défi Multi-Tenant & Hibernate

Q1 : Comment empêchez-vous STRICTEMENT une fuite de données entre deux établissements dans Spring Boot ?

Si vous mettez juste WHERE tenant_id = ? dans vos repositories Spring Data, un développeur étourdi va tôt ou tard écrire une requête native ou oublier le filtre, exposant les données de l'EMSI à une autre université.

Solution attendue : Utiliser @TenantId natif d'Hibernate 6 (qui injecte automatiquement le tenant dans toutes les requêtes JPQL/Criteria) ou des politiques PostgreSQL Row-Level Security (RLS) avec SET app.current_tenant = ... avant chaque transaction de connexion !
Défi Moteur IA & Ollama

Q2 : Que se passe-t-il si Ollama hallucine, plante ou met 45 secondes à répondre ?

Si l'appel HTTP vers Ollama est synchrone dans un contrôleur Spring Boot REST, le thread pool Tomcat s'épuise et l'application s'effondre. De plus, un LLM peut renvoyer du Markdown non parseable au lieu de JSON.

Solution attendue : Architecture asynchrone (Job queue avec statut EN_COURS), format JSON garanti avec mode format: "json" d'Ollama + validation Pydantic/Java Jackson, et fallback déterministe par recherche de mots-clés si le LLM est indisponible.
Défi Planification & OR-Tools

Q3 : Générer un emploi du temps pour 3000 étudiants et 150 profs est un problème NP-Complet. Si OR-Tools ne trouve pas de solution parfaite, que fait le système ?

Dans la vraie vie, il y a trop de contraintes (un prof ne veut que le mardi, les salles GPU sont pleines). Un solveur rigide renvoie simplement "UNSATISFIABLE" et échoue.

Solution attendue : Séparer les contraintes en Hard Constraints (zéro chevauchement physique) et Soft Constraints avec pénalités pondérées (préférences horaires). Fournir une interface d'assistance visuelle de résolution des conflits pour le planificateur.
Défi Présence & Fraude Mobile

Q4 : Comment empêcher un étudiant resté chez lui de scanner une photo du QR Code envoyée sur WhatsApp par son camarade en amphi ?

Les étudiants sont ingénieux. Un simple QR code statique est instantanément capturé en photo et partagé dans le groupe WhatsApp de la promo.

Solution attendue : Double barrière : (1) QR code tournant généré avec TOTP (validité 10s max) et (2) Vérification de la géolocalisation GPS du mobile ou restriction à l'adresse IP du Wi-Fi campus de l'EMSI.
